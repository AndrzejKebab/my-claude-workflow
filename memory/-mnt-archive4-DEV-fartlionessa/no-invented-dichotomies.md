Don't invent dichotomies for the sake of framing. When one rule already covers both branches,
state the rule — don't dress it up as a per-project distinction or a fork the user must pick.

**Why:** Observed this session — I framed "live editor → unity-cli vs no editor → batchmode" as a
fartlionessa-specific workflow trait. The user corrected: it's the SAME universal Unity rule across
all their projects (all zori-testbed projects declare the unity-cli connector too), already in
global CLAUDE.md. Manufacturing the distinction added noise and a fake choice.

**How to apply:** Before presenting A-vs-B or calling something project-specific, check whether a
single existing rule (global CLAUDE.md, an established convention) already decides it. If so, apply
the rule silently and move on. Reserve genuine forks for real, evidence-free preference picks. See
also the "Lead with evidence, not a menu" rule in this repo's docs/agent-working-rules.md.
