The 2026-07 "grey rock until terrain toggle" bug was four stacked defects, each individually capable of baking wrong VT content that nothing ever repairs (fixed on `feat/stamp-target` 43dc521/e0c1a16 + gated by `SplatDemoSceneFirstLoadTests` and `VTFillDeliveryTests`):

1. **Edit-mode clocks freeze.** `Time.frameCount` stays 0 and `Time.deltaTime` stays 0 in edit mode: any once-per-frame guard keyed on frameCount runs ONCE per enable, and any accumulator fed by deltaTime starves. Use `Time.renderedFrameCount` for frame identity and `Time.realtimeSinceStartup` deltas for pacing. Shadow-domain code still uses `Time.frameCount` (`ShadowBuffer`, `ShadowRefreshSchedule`) — same trap if shadows ever need edit-mode correctness.
2. **Publication ≠ delivery.** `VTHandle.UpdateCpuPhase` publishes pending/dirty state, but the fill body runs only if something records it that frame (render feature during a camera render, or headless execute). Tiles are allocated/resident at publish time, so a lost delivery = resident-forever garbage. The delivery latch (`_fillDelivered`/`MarkFillDelivered`) holds the phase until the fill body ran; keep it when touching `UpdateCpuPhase`/`DispatchFill`.
3. **Weight functions must be pure functions of (tile, mip, delivered inputs).** Splat stamps sampling height through the page-table lookup depend on global streaming state (misses outside the toroidal window return 0 → gradient explosion → all-bands-pass weights); finest-texel gradient steps make baked weights depend on what resolution was sampled at composite time. The fixed form: tile-local reads of the composited tile's padded pool rect (`SampleTileHeightNorm`) + gradient steps of one texel of the tile's own mip. Any new stamp weight function must follow this or first-load vs re-enable diverge again.
4. **`List.Sort` is unstable; registration order differs between scene load and re-enable.** Tied `order` values with non-commuting blends (Max vs Additive on a shared channel) bake different pools per standup. `TerrainStampSet` tie-breaks on the hierarchy path — keep any new registry sort stable against enable order.
5. **The slope-stamp degree convention is the NORMALIZED-field gradient (`Δh_norm/Δuv`), not the physical slope.** They differ by `terrainSize.y / terrainSize.xz`; the normalized form is scale-independent by construction and `SplatDistribution_SurvivesTerrainResize` is its spec. When slope moved to the `_NormalOS` layer (2026-07), the physical `acos(n.y)` form silently rescaled every authored band and broke resize invariance — the fix reconstructs the normalized gradient from the physical normal (`SampleTileGradientUV`: `-n.xz/n.y · sizeXZ/heightRange`). The layer itself stays physical (rendering needs the true normal).

6. **Fill tile lists must ride the command stream.** The shared tile-assignment GraphicsBuffer is mutable global state: a main-thread `SetData` can be clobbered by a later tick (deferred RenderGraph submission, editor multi-view double ticks) or by the same tick's resident-over-pending upload, so a recorded instanced fill draws the WRONG TILES at execution. Victims are one-shot bakes of just-written content (splat weights reading `_NormalOS` — random per-tile corruption healing on motion, live-editor only). Fixed form: snapshot the tile list at record, `cmd.SetBufferData` in-stream immediately before every consuming dispatch/draw (`FulfillerArgs.PendingTiles/ResidentTiles`, `NormalFill`, `BasemapFill`); `EnsureAssignmentCapacity` is the only main-thread buffer op. Gate: `PendingFillIntegrityTests`.

7. **Tile-local pool taps must clamp to TEXEL CENTERS, not the rect edge.** `StampTilePoolUV`'s `clamp(tileUV,0,1)` mapped uv=1 to `rect.xy + rect.zw` — the boundary shared with the ADJACENT PHYSICAL SLOT — so a bilinear tap there blends half a texel of whichever tile the allocator keeps next door: slot-neighbourhood state, standup-history-dependent. A cavity Laplacian (×20 strength, world-radius taps = whole clamp bands at coarse mips) amplified that half-texel into visibly different splat patches per standup (the live-editor "waterfall"/patchwork tiles that healed on toggle). Fixed form: `clamp(uv·rect.zw, 0.5, rect.zw − 0.5)`. Gate: `SplatStreamingFlightTests` (fly the demo-scene camera, then compare against a toggle recomposite — the static first-load gate cannot see this class).

**How to apply:** any "wrong until toggle / restart" symptom in this repo — check these seven before theorizing; the unity-cli live-editor readback loop (`VTContentView.Sample` via exec) plus a batch playmode scene-load repro was the evidence path that cracked it. When two composites of the same tile disagree with "identical" inputs, capture inputs AND outputs IN-STREAM at bake time (`cmd.CopyTexture` to debug RTs) and bisect per draw stage — uniform logs alone missed this twice.
