`mmodb` (`/mnt/archive4/DEV/mmodb`, repo `api-haus/mmodb`, private) speeds up SpacetimeDB server modules written in TypeScript by adding an ahead-of-time compile path. The user develops MMO server logic in TypeScript on the normal SpacetimeDB toolchain (rolldown→single-JS→embedded V8); **release** builds instead compile the same TS with a forked [Perry](https://github.com/PerryTS/perry) into a freestanding `wasm32` module that satisfies SpacetimeDB's stable, language-agnostic native ABI (`spacetime_10.0`–`10.5` host imports; `__describe_module__`/`__call_reducer__` exports — `crates/bindings-sys/src/lib.rs`) and is loaded by the **stock** Wasmtime host exactly like Rust/C#/C++ modules.

The two forks (the only fork surface — SpacetimeDB **core/host is never modified**): **`api-haus/perry`** (fork of `PerryTS/perry`: add a freestanding `wasm32-unknown-unknown` LLVM target, port the `perry-runtime` core to wasm32, add ABI plumbing) and **`api-haus/SpacetimeDB`** (fork of `clockworklabs/SpacetimeDB`: one extra "compile with Perry for release" option in `crates/bindings-typescript` + `crates/cli`, lowering the `spacetimedb/server` API onto the ABI like the C#/C++ bindings do; the Perry fork is embedded here).

Canonical plan and investigation live in `docs/orchestrate/perry-stdb-poc/` (00–08b). The code at `file:line` is the source of truth; those docs are working memory. See [[no-perrywasm-host-fork]] for the rejected approach. Multi-week effort (6 milestones, ~4–7 weeks) started 2026-05-31.

**Progress:** Both forks aligned with upstream (perry `main` `ed633ca`, STDB `master` `d31301a8`; the `gh` token now has the `workflow` scope needed to sync the STDB fork). **M1 done + verified** — a `--target spacetimedb` in the forked Perry compiles trivial TS to a freestanding `wasm32` module (zero `rt`/`ffi`/`env` imports) via the LLVM path, on `api-haus/perry` branch `feat/target-spacetimedb` (commits `d57ba1cc` runtime-port + `03661376` M1). **M2 make-or-break spike done + verified (central risk retired):** the forked Perry toolchain emits named/typed `__describe_module__`/`__call_reducer__` dunders + a `spacetime_10.0` import + an addressable static BSATN def (via clang `export_name`/`import_module` attrs, the C++ `abi.h` mechanism), and the 770-byte module **publishes to the stock v2.0.1 server, instantiates, and the reducer is callable** (commit `42ae9659` on `feat/target-spacetimedb`). The ABI shim is C authored by the `--target spacetimedb` step, compiled+linked by Perry's own toolchain.

**Next = M2-proper / M3 / M4 (follow-through, not unknowns):** (1) generate the BSATN `RawModuleDef::V10` from the user schema/`registerReducer` walk instead of the hand-built fixed `noop` def; (2) real `__call_reducer__` dispatch (`bytes_source_read` → BSATN decode → call user `perry_fn_*` → error sink); (3) link the wasm32 `libperry_runtime.a` for runtime-touching reducers — the shell-amputation long pole (M1/M2 use `wasm-ld` with no `--allow-undefined`, so an undefined symbol is the designed signal to link the archive); (4) prove Perry's own HIR→LLVM can emit the `export_name`/`import_module` attrs directly (the C-shim sidesteps this); (5) M3 move the shim into the TS runtime + replace `sys.d.ts` with `spacetime_10.x` import decls; (6) M4 the `--engine perry` flag. B4 NaN-canonicalization confirmed clean for integer kernels only. A stock SpacetimeDB **v2.0.1** server runs locally via `docker-compose.yml` on `:3000`.

**Benchmark plan (user chose full-path, in sequence): (1) raw-TS V8 baseline → (2) Perry empty+CPU-kernel → (3) M3 datastore workloads.** Reuse SpacetimeDB's own suite `crates/bench` (generic over `ModuleLanguage`); `modules/benchmarks-ts` already mirrors the Rust workloads. The perf suite wires only Rust+C# by default — adding the TS arm (and later a `TypeScriptPerry` arm = same source via `--engine perry`) is the change. **Step 1 done + verified** on `feat/perry-release-engine`: empty-reducer **call overhead is language-independent (Rust 7.14µs ≈ TS-V8 7.20µs, host-dominated)**; TS is 2–5× slower only on compute (print_bulk 4.87×, circles 2.27×, ia_loop 1.98×). Two bounded blockers: TS generic-table workloads need a `benchmarks-ts` reducer-name fix (explicit names skip the SnakeCase `u32`→`u_32` conversion the harness applies — also blocks the Perry arm); C# arm needs the `Microsoft.NET.Runtime.WebAssembly.Wasi` pack. Each `cargo bench` run is ~50 min.
