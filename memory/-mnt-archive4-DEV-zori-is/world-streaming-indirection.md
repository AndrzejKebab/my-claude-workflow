zori.is world streaming (pseudo-infinite, OPFS-persisted, following `/mnt/archive4/DEV/bevy_pixel_world`) uses a **chunk-tile indirection** resident window: array of chunk slots, scroll = reassign world-chunk→slot mapping (zero copy). Sim resolves a chunk-slot pointer per chunk/tile, not per cell.

**SUPERSEDED — the flat-toroidal "cut" is GONE (reworked to EXPLICIT slot indirection).** The original Phase-1 sim accessed the buffer PHYSICALLY (flat `y*width+x`) with a moving `WorldDims.cut` move-guard refusing swaps across the wrap. That cut was a real on-screen discontinuity (blocked flow + paint bleed) visible every WINDOW_CHUNKS chunks — the apron-hides-seam claim only held at 6×6, but the code shipped 3×3 so the seam was in the viewport. Now: the SIM addresses LOGICAL window coords `[0,WINDOW_PX)`; `WorldDims::cell_index`/`tile_at` resolve each to its physical slot via `(slot0 + lx/CHUNK) mod WINDOW_CHUNKS` where `slot0=origin_chunk mod WINDOW_CHUNKS` is published per tick (control word, workers pin `streaming=true`). No wrap, no seam, no apron — **WINDOW_CHUNKS is a free (settings/per-device) parameter**. Window edge rigid via `in_bounds` (material piles, no drain — `try_flow_out` seals under streaming). Removed: `crosses_cut`/`NO_CUT`/`cut_x/cut_y`/`is_ring`/`W_CUT_*`. Physical layout (`slot_of_chunk` modulo) + all consumers (render/input/particle via `ring_cell_index`/`buffer_to_world`) UNCHANGED — the whole rework is contained to the sim's two resolvers + removing the cut. Lesson: when the user reports SEEING an artifact, trust the observation and diagnose the real cause; don't explain why it "should" be hidden. Initial window now primed at boot (`stream_prime`).

**Why:** memmove shift-on-scroll cannot guarantee stable per-frame perf on mobile (unbounded multi-MB wasm `memory.copy` per scroll), and buys nothing at the speed limit (full-window traverse → 0 overlap → nothing to copy). Indirection is proven in the reference and all prior implementations. See `docs/orchestrate/world-streaming/03-scroll-strategy.md`.

**How to apply:** memmove is a deferred optimization only — revisit only with on-device e2e numbers [[benchmarks-in-app-e2e-on-device]]. Decisions/maps live in `docs/orchestrate/world-streaming/` (00 current arch, 01 reference design, 02 reference impl, 03 scroll strategy, 04 sim-on-ring) and `docs/streaming/` (coordinates, persistence, manual-qa).
