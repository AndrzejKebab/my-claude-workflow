Built 2026-06-24. An independent, extensible character-controller + camera + modular-avatar foundation on top of the ALS-Refactored plugin (`Plugins/ALS-Refactored`, plugin name `ALS`, submodule — NEVER edit its C++ or `/ALS/` content; subclass/reference/duplicate-out only).

C++ in `Source/FARTS/` (deps added to FARTS.Build.cs: `ALS, ALSCamera, GameplayTags, Voxel, VoxelCore`):
- `AFartsCharacter : AAlsCharacter` — clone of `AAlsCharacterExample` (EnhancedInput + `UAlsCameraComponent`); `Input_OnAim` overridden to ALSO set overlay (RMB = pistol raise + aim: `SetOverlayMode(PistolOneHanded)` + `SetDesiredAiming(true)`, release restores `Avatar->GetBaseOverlayMode()`). Holds `UFartsAvatarComponent* Avatar` + two Voxel invokers (`UVoxelCollisionInvokerComponent`, `UVoxelCameraInvokerComponent`) as subobjects (the "voxel character" requirement — component path, since single-inheritance is taken by AAlsCharacter). `PostInitializeComponents` calls `Avatar->BuildAvatar()` BEFORE `Super` (ALS caches the anim instance at line ~132 of AlsCharacter.cpp).
- `UFartsAvatarComponent` + `UFartsAvatarConfig` (UPrimaryDataAsset: `BodyType` enum, `BodyMesh`, `BodyAnimClass`, `Parts` TMap) — the avatar system: builds the body from parts via Leader Pose, sets leader mesh + AnimClass from config, and maps BodyType→base ALS overlay (Masculine/Feminine). Gender is an avatar config property, NOT a pawn flag.
- `AFartsGameMode` (PlayerControllerClass=AFartsPlayerController in ctor), `AFartsPlayerController` (thin).

Content in `Content/_Project/Characters/`: `BP_FartsCharacter` (camera mesh `/ALS/ALSCamera/SKM_Als_Camera` + AnimBP `AB_Als_Camera`, avatar config default `DA_Avatar_Masculine`, input = ALS originals), `BP_FartsGameMode`, `BP_FartsPlayerController`, `ABP_FartsBody` (child of `AB_Als`, skeleton `SK_Als`), `DA_Avatar_Masculine/Feminine` (SKM_BodyA/B + MageSet01 FullSet outfit via Leader Pose). Test map `/Game/_Project/Maps/L_CharacterSandbox` (GameMode override set; NEEDS floor + PlayerStart added headful — commandlet can't persist level actors).

Skeleton/retarget strategy (linchpin, REWORKED 2026-06-25): compatible-skeleton playback was REPLACED by **runtime IK retargeting** (the compatible-skeleton path stretched the stylized body — "Men in Black" long neck/small head — because ALS bone TRANSLATIONS sized for the mannequin got imposed on a differently-proportioned body). New two-mesh architecture (all driven through Unreal MCP / `-run=pythonscript`):
- `CharacterMesh0` (the ACharacter main mesh) is now the HIDDEN animation SOURCE: `SKM_Als` (skeleton `SK_Als`) running `ABP_FartsBody`. Hidden via `SetVisibility(false)`. This keeps ALS's `UAlsAnimationInstance` cast + camera socket queries valid (matches ALS's own example which uses SKM_Als as the main mesh).
- CRITICAL GOTCHA (frozen-figurine bug, hit 2026-06-25): a hidden source mesh must keep ticking its pose or the retarget copies a frozen pose. Setting `VisibilityBasedAnimTickOption=AlwaysTickPoseAndRefreshBones` at runtime does NOT stick — `AlsCharacter::RefreshVisibilityBasedAnimTickOption` (called every tick) overwrites it with `FMath::Min(TargetTickOption, DefaultTickOption)` where DefaultTickOption = the CDO's mesh value. So set it on the CDO: in `AFartsCharacter` ctor `GetMesh()->VisibilityBasedAnimTickOption = AlwaysTickPoseAndRefreshBones` (enum 0 = ticks most; Min keeps it). Verify live in PIE: tickOpt must read 0, and the source pose must change every frame (frozen = a constant; animating = oscillates).
- A new VISIBLE child `FartsBodyMesh` component holds the stylized body (`SKM_BodyA`/`SKM_BodyB`) and runs `UFartsRetargetAnimInstance` (C++, `Source/FARTS/FartsRetargetAnimInstance.{h,cpp}`) — a minimal `UAnimInstance`+`FAnimInstanceProxy` hosting one `FAnimNode_RetargetPoseFromMesh` (`RetargetFrom=ParentSkeletalMeshComponent` auto-sources the attach-parent CharacterMesh0). Needs Build.cs dep `IKRig`. The proxy mirrors the engine's editor `FIKRetargetAnimInstanceProxy` (Initialize/CacheBones/UpdateAnimationNode/Evaluate + GetCustomRootNode/GetCustomNodes for game-thread PreUpdate). The retargeter asset is pulled from the avatar config in `NativeInitializeAnimation` (robust; survives anim-instance recreation) + set imperatively in `RebuildBody`.
- Head/outfit parts now Leader-Pose to the VISIBLE `FartsBodyMesh` (they are BodyA/B-skeleton meshes), not CharacterMesh0.
- IK assets in `/Game/_Project/Characters/Rigs/`: `IK_Als`, `IK_BodyA`, `IK_BodyB` (auto-generated retarget definition: pelvis root + Spine/Neck/Head/arms/legs chains) and retargeters `RTG_Als_To_BodyA`/`_BodyB` (`add_default_ops` stack = Pelvis Motion, FK Chains, Run IK Rig, Root Motion, Remap Curves; `auto_map_chains(EXACT)`). GOTCHA: do NOT run `auto_align_all_bones` — SK_Als and SK_BodyA share orientation conventions (pelvis/neck ref rotations ~identical; spine euler deltas are gimbal aliasing near pitch 90, not real), so aligning the target retarget pose introduced a constant ~90° forward bend. Fix = `reset_retarget_pose(poseName, [], SourceOrTarget)` (note middle `BonesToReset` arg) on SOURCE+TARGET to ref. Avatar config (`UFartsAvatarConfig`) gained `SourceMesh`, `SourceAnimClass` (was BodyAnimClass), `Retargeter`; `BodyMesh` stays the visible stylized mesh.
Setting `OverlayMode` on the source still drives overlays — `AB_Als` auto-links overlay layers by gameplay tag.

A programmatically-created `AAlsCharacter` child BP needs the asset refs the ALS example `B_Als_Character`/`B_Als_CameraComponent` carry that a bare BP child lacks (all hit + fixed during 2026-06-24 QA):
- `Settings` = `/ALS/ALS/Data/Character/CS_Als_Default` and `MovementSettings` = `/ALS/ALS/Data/Character/Movement/MS_Als_Normal` — null on a bare BP, ALS dereferences `Settings` unchecked on possess (`AlsCharacter.cpp:513` segfault).
- GameMode `PlayerControllerClass` must be a class that exists on disk (a reference to an unsaved BP gets nullified at load -> "Failed to spawn player controller").
- Camera component `Settings` = `/ALS/ALSCamera/Data/CS_Als_Default` (a `UAlsCameraSettings`, protected/no C++ setter -> must be set on the BP/CDO, not C++) — null = camera won't follow.
- The leader `CharacterMesh0` needs `SkeletalMeshAsset`+`AnimClass` set as BP DEFAULTS (`SKM_BodyA` + `ABP_FartsBody`), not just at runtime by the avatar — else on frame 0 the ALS camera queries sockets on an empty mesh ("No SkeletalMesh for Component(CharacterMesh0)") and never anchors. The C++ ctor already sets the mesh transform (`-92` Z, `-90` yaw) + capsule (30/90).
- `SKM_BodyA` is a headless modular body: the head is a separate `SKM_HeadA_01` (`BodyB` -> `SKM_HeadB_01`) attached via Leader Pose; the avatar config `Parts` map needs a `Head` entry or the character is headless.
- The "Men in Black" long-neck/small-head stretch is SOLVED by the runtime IK-retarget architecture above (NOT translation-retargeting modes, NOT compatible-skeleton). Verified upright + correctly-proportioned in real PIE (StartPIE -> CaptureEditorImage, before/after: auto_align bent ~90° -> reset-to-ref upright). Objective ref-pose baseline (global, via `IKRigController.get_ref_pose_transform_of_bone`): head_z Als 165.5 vs BodyA 163.0 vs BodyB 159.0; source/target bone lengths differ -> why compatible-skeleton stretched, why FK-chain retarget (rotation-match, target keeps own lengths) fixes it.
Visual verification of the real gameplay pose (editor preview of an ALS char is a contorted artifact - no game state; `CaptureViewport` only renders the editor world, not PIE): `StartPIE` via MCP (works on a headful editor once the char no longer crashes) then `EditorAppToolset.CaptureEditorImage` (captures the whole editor incl. the live PIE viewport), then `StopPIE`.
Reusable headless test: `Scripts/validate_farts_character.py` (asserts all the above; `[FARTS-TEST] PASS`). Sandbox map `L_CharacterSandbox` populated (floor/PlayerStart/lighting incl. real-time-capture SkyLight) via MCP SceneTools + `AssetTools.save_assets`.

Avatar generator + overlay linking (added 2026-06-25): `AFartsCharacter` gained the demo "quick avatar preset switch" and a real overlay-linking fix.
- **Overlay-linking gotcha (root bug):** ALS overlay modes (Feminine/Masculine/PistolOneHanded) are LINKED ANIM LAYERS — a tag only changes the visible pose when something calls `Mesh->LinkAnimClassLayers(overlayAnimBP)`. `AB_Als`'s internal `Overlay` graph is a no-op ref pose; the ALS DEMO does the linking in the **`B_Als_Character` Blueprint** (`OnOverlayModeChanged` → `RefreshOverlayLinkedAnimationLayer` using its `OverlayAnimationInstanceClasses` TMap<tag,AnimBP>). The C++ template `AAlsCharacterExample` does NOT link overlays. `AFartsCharacter` is a C++ child of `AAlsCharacter` (not of `B_Als_Character`), so before this fix overlays were set as tags but **never visually applied** — women were never feminine. Fix: `AFartsCharacter::OnOverlayModeChanged_Implementation` + `BeginPlay` call `RefreshOverlayLinkedAnimationLayer()`, which `LinkAnimClassLayers(GetMesh(), ResolveOverlayAnimationInstanceClass())` on the SOURCE mesh (CharacterMesh0/ABP_FartsBody) — the overlay flows through the IK-retarget to the visible body. Verified live in PIE: man→`AB_Als_Masculine`, woman→`AB_Als_Feminine`, no crash.
- New `AFartsCharacter` UPROPERTYs (set in `BP_FartsCharacter` defaults): `AvatarPresets` (TArray<UFartsAvatarConfig*>, the 6 presets), `OverlayAnimationInstanceClasses` (TMap<FGameplayTag,TSubclassOf<UAnimInstance>> → ALS overlay AnimBPs), `FemininePistolOverlayAnimationInstanceClass` (combined feminine+pistol overlay; UNSET — asset not yet authored, falls back to PistolOneHanded), `SwitchAvatarAction` (IA_Farts_SwitchAvatar). `Input_OnSwitchAvatar` cycles presets via `Avatar->SetConfig` then re-links overlay. `ResolveOverlayAnimationInstanceClass` routes feminine+PistolOneHanded → FemininePistol when set.
- 6 presets in `Content/_Project/Characters/`: `DA_Avatar_Masculine`/`_Feminine` (mage, MageSet01 FullSet; man mage also has hair `SKM_HairstyleA_13` + cape `SKM_BodyA_Mage_Cape_01`), `DA_Avatar_Casual_M`/`_F` (CasualSet02 FullSet), `DA_Avatar_Elf_M`/`_F` (CasualSet04_Elves FullSet). All parts leader-pose by matching bone names (each Synty piece has its own skeleton asset but shared bone names — that's why leader pose works across them).
- Input: `BP_FartsCharacter.InputMappingContext` is now `IMC_Farts_Default` (a full clone of `IMC_Als_Default` + `N`→`IA_Farts_SwitchAvatar`); it is the SOLE primary context (AvatarInputMappingContext left null to avoid double-mapping). Add IMC key mappings with the python `imc.map_key(action, unreal.Key()/.set_editor_property("key_name","N"))` in a commandlet — MCP `set_properties` on `defaultKeyMappings` fails to grow/shrink the array.
